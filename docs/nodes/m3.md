# M3: fire, wind, spark

Three finished-recipe models of the elements (`crates/sfx_graph/src/nodes/elements.rs`),
each a few physical fields in, tuned DSP inside. All three are seeded, take a
`loop` field that makes the render periodic in the document's duration, and
are checked in `crates/sfx_analysis/tests/m3.rs`. Examples that render a WAV
and a PNG and print the descriptors: `examples/fire.rs`, `examples/wind.rs`.

## The `loop` field (all three nodes)

`loop` is an optional bool. Unset, it follows the document: a `kind: loop`
document gets the periodic render, a oneshot does not. `loop: true` forces it,
`loop: false` forces the plain render (the control signals then start and end
at unrelated values). What the periodic render does:

- every slow random control (fire turbulence, wind gusts, the whistle waver)
  is a lattice with a whole number of cells in the buffer, indexed modulo that
  number, so the value at the end is the value at the start; the lattice rate
  is rounded to fit (at least one cell);
- a random impulse that rings past the end is written back to the start;
- the filters run over the whole buffer twice with the same input and keep the
  second pass, so the state at sample 0 is the state at the end (exact up to
  the filter ring-down, a few milliseconds);
- the wind whistle phase gets a linear correction of at most half a cycle over
  the buffer; the spark mains envelope is retuned to a whole number of cycles
  (at most `0.5 / duration` Hz off);
- spark strike times become a jittered grid (one strike per `1 / rate` cell)
  instead of a Poisson process, so a short loop's head and tail hold about the
  same number of strikes.

A signal you feed `intensity` or `speed` is yours: make it periodic too (an
`lfo` whose frequency is a multiple of `1 / duration`). The node's `causal()`
is false only when `loop` is explicitly true (the two passes need the whole
buffer); with `loop` unset in a loop document the render is periodic but the
flag still says causal.

## `fire`

Fire (source model): a low roar, a high hiss and crackle pops under one shared
control (intensity times a slow turbulence).

### Fields

| Field | Type | Default | Range / unit | What it does |
|---|---|---|---|---|
| `size` | number | required | 0.02 .. 10 m | Flame size. The roar's 24 dB/oct low-pass corner is `260 / sqrt(size)` Hz (clamped 40..1500), its level rises as `size^0.35`, pops are pitched `(1/size)^0.15` lower. |
| `intensity` | signal | `0.5` | 0 .. 1 | Burn rate. A number outside 0..1 is an error; a signal is clamped per sample. Raises the roar (`0.25 + intensity`), the hiss (`intensity^2`), the pop rate and the pop heights together. |
| `crackle` | number | `0.5` | 0 .. 1 | Pop rate multiplier; 0 is no pops. Pops a second are `2 * crackle * (3 + 90 * intensity^2)` times a turbulence factor of 0.6 to 1.4 (at most about 260). |
| `seed` | integer | `0` | | Mixed with the document seed and the node name. |
| `loop` | bool | unset | | See above. |

Pops: a Poisson process thinned per sample; heights `min(0.1 / u, 1.5)` with `u`
uniform in (0, 1) (a power law with exponent 1, capped), each a two-pole ring at
a log-uniform 900..5500 Hz with a 60 dB decay of 2 to 8 ms, random sign. The
turbulence is three lattice octaves (1.3, 3.5 and 9.5 cells a second). Work caps:
no field sets a count; the pop rate is bounded by the formula above and each
pop is at most 8 ms of samples.

### Recipe

A campfire loop; give the human macros on `size` (weight) and `intensity`
(how hard it burns).

```json
[
  {"type": "fire", "name": "flames", "size": 0.7, "intensity": 0.6, "crackle": 0.6, "seed": 3},
  {"type": "onepole", "name": "clean", "input": "flames", "mode": "hp", "freq": 30},
  {"type": "output", "name": "out", "input": "clean", "lufs": -28}
]
```

as an 8 s `kind: loop` document (`examples/fire.rs`).

### Honest limits

- The pop-size slope is below 1 (0.78 to 0.86): the cap at 1.5, the detection
  floor and the band-pass gain (which depends on each pop's pitch) bend a
  measurement of the distribution, so the test bound is loose (0.6 to 1.4).
- Pops are quiet next to the roar at low intensity (heights scale with
  `0.4 + 1.2 * intensity`) and are masked by the hiss at high intensity; the
  count above is of pops that clear the band-passed floor, not of all pops.
- `crackle: 0` gave 2 detected events in 10 s: the detector's own false
  positives (robust sigma on a band that still holds a little roar and hiss).
- Not normalised: the default render is about -30 LUFS with a peak near -8 dBFS;
  set `output.lufs`. A pop-heavy fire is peaky (crest 23.5 dB in the example at
  -24 LUFS, which reached the output limiter; the recipe uses -28).
- Memory is six buffers of the document length (about 700 MB at 600 s).
- None of this has been heard.

## `wind`

Wind (source model): white noise through five resonant band-passes whose centres
and gains follow the speed, a fractal gust, and an optional Aeolian tone.

### Fields

| Field | Type | Default | Range / unit | What it does |
|---|---|---|---|---|
| `speed` | signal | required | 0 .. 60 m/s | Wind speed. A number outside is an error; a signal is clamped per sample. 0 is exact silence. Band `k` sits at `base_k * (0.6 + 0.8 * (v/20)^0.8)` Hz (bases 120, 280, 600, 1200, 2400; Q 2.5, 3, 3.5, 4, 4.5) with gain `weight_k * min(v/20, 2.5)^(0.8 + 0.3 k)`, so the upper bands rise faster. Centres stop at 0.45 times the sample rate; levels stop growing at 50 m/s. |
| `gust` | number | `0.3` | 0 .. 1 | How far the speed swings: `v * (1 + 0.6 * gust * fbm)` with fbm three lattice octaves at 0.4, 1.1 and 2.9 cells a second (about -1..1). |
| `whistle` | number | `0` | 0 .. 1 | Level of a sine at `0.2 * v / diameter` Hz (v the gusting speed), amplitude `whistle * 0.12 * min(v/20, 2.5)^2` with a 3 cells a second waver of +-30 %. 0 adds nothing. |
| `diameter` | number | `0.004` | 0.0005 .. 0.1 m | The object the wind blows past; sets the whistle pitch. (Not on the card; the card's whistle formula needs it. Add or drop at integration.) |
| `seed` | integer | `0` | | Mixed with the document seed and the node name. |
| `loop` | bool | unset | | See above. |

Work caps: no field sets a count. Five band-passes per sample (a TPT state
variable filter, stable under per-sample retuning).

### Recipe

A gale with a wire whistle; give the human macros on `speed` (strength) and
`gust` (gustiness; its claim is `swing`).

```json
[
  {"type": "wind", "name": "gale", "speed": 12, "gust": 0.6, "whistle": 0.3, "diameter": 0.004, "seed": 5},
  {"type": "output", "name": "out", "input": "gale", "lufs": -26}
]
```

as an 8 s `kind: loop` document (`examples/wind.rs`). For a swell, feed `speed`
a `ramp` or a periodic `lfo`.

### Honest limits

- The five bands are a spectral recipe, not a boundary-layer model: the
  centre and gain laws were set so the stated measures move, nothing was fitted
  to recordings.
- The band-pass gains are normalised for equal noise power per band; the
  absolute level is tuned by ear-less choice (about -29 LUFS at 8 m/s, peak
  -15 dBFS), use `output.lufs`.
- With gust 1 the effective speed can reach 1.6 times `speed` and drop to 0.4
  times it; `speed` itself is clamped to 60.
- The whistle is one sine that follows the gusting speed, with no harmonics
  and no lock-in jumps between shedding modes.
- In a loop the gust lattice is rounded to a whole number of cells: a 1 s
  loop has one cell at 0.4 a second, so the gust is then a constant.
- Memory is five buffers of the document length (an `f64` phase buffer too with
  a whistle).
- None of this has been heard.

## `spark`

Spark (source model): an electric arc that keeps re-striking, gated by the mains
waveform, into a short resonator.

### Fields

| Field | Type | Default | Range / unit | What it does |
|---|---|---|---|---|
| `rate` | number | required | 0.1 .. 200 strikes a second | How often an arc starts (Poisson; a jittered grid in a loop). Each strike is a snap of height 1 plus 20 to 70 ms of impulses at 3000 a second, random sign, heights 0.2..1 times the mains envelope. |
| `buzz` | number | `50` | `50` or `60` Hz | Mains frequency. The envelope is `\|sin(2 pi f t)\|^1.5` (period `1 / (2 f)`) with every odd half-cycle at 0.75, so the modulation is strongest at `2 * buzz` and a weaker line sits at `buzz`. Any other value is an error. |
| `body` | number | `3000` | 200 .. 12000 Hz | A 2-pole resonator ringing 3 ms (60 dB); a second at 1.9 times it (2 ms, half gain) when under 0.45 times the sample rate. |
| `seed` | integer | `0` | | Mixed with the document seed and the node name. |
| `loop` | bool | unset | | See above. |

Work caps: `rate` is capped at 200, so a strike count is at most 200 times the
duration, each with at most 210 impulses.

### Recipe

A sparking cable; give the human macros on `rate` (how angry) and `body`
(brightness; its claim is `centroid`).

```json
[
  {"type": "spark", "name": "arc", "rate": 6, "buzz": 50, "body": 3000, "seed": 1},
  {"type": "output", "name": "out", "input": "arc", "lufs": -24}
]
```

|---|---|---|
| `buzz` 50, rate 20 (4 s): strongest line of the envelope spectrum (`\|x\|` smoothed at 300 Hz, 20..400 Hz) | 100.0 Hz, 31.1 dB over the median of that range | `spark_is_modulated_at_the_mains_rate` |
| same: line at 50 Hz | 21.4 dB over the median | same |
| `buzz` 60, rate 20 | peak 119.9 Hz (30.2 dB); line at 60 Hz 19.0 dB | same |
| `buzz` 50, rate 5 | peak 100.0 Hz, 26.7 dB over the median | same |
| `body` 1000 / 3000 / 8000 Hz: centroid | 1076 / 3269 / 9141 Hz | `spark_body_moves_the_centroid_and_rate_the_loudness` |
| `rate` 2 / 8 / 32: lufs | -33.5 / -29.4 / -23.6 | same |
| loop, 1.31 s (65.5 mains cycles): envelope peak | 101.07 Hz (retuned to a whole number of cycles; 100.76 expected) | `the_spark_mains_is_retuned_to_whole_cycles_in_a_loop` |
| `kind: loop`, unset (rate 15) and `loop: true` (rate 8, 60 Hz) | `loop_seam` wrap 0.00x and 0.02x, spectral change 1.6 and 0.9 dB | `a_loop_document_of_each_node_passes_the_default_checks` |
| 30 s, rate 200, loop | 0.08 s | `the_elements_render_in_a_time_budget` |

### Honest limits

- The mains lines are in the amplitude envelope of the arc, not a 50 Hz hum
  tone: the spectrum itself has no line at 50 or 100 Hz.
- A sparse spark (`rate` under about 10) can fail the `loop_seam` spectral term by
  content variation alone: with Poisson strike times a 3 s loop at rate 8 and 60 Hz read
  7.2 dB (limit 6). The periodic render uses a jittered grid and read 0.9 dB, but a
  non-loop (`loop: false`) sparse spark can still fail it.
- The arc has no physical model of a gap (voltage, length); `rate`, `buzz` and
  `body` are the whole front panel.
- None of this has been heard.

## Extremes

Fire (size 0.02 and 10, intensity 0 and 1, crackle 0 and 1), wind (speed 0,
0.001 and 60, gust 0 and 1, whistle 1, diameter 0.0005 and 0.1), spark (rate
0.1 and 200, body 200 and 12000, both mains), each with `loop` on and off, a
ramp signal on `speed` and on `intensity` running from -1e9 to 1e9, and a 4 ms
spark loop: all finite, largest peak 1.77 (`the_elements_are_finite_and_bounded_at_the_extremes`).

## Errors

- `size: 40: give metres from 0.02 to 10 (candle 0.03, campfire 0.6, bonfire 3)`
- `intensity: 2: give a number from 0 to 1`
- `speed: 90: give metres a second from 0 to 60`
- `rate: 500: give strikes a second from 0.1 to 200`
- `buzz: 55: give 50 or 60 (the mains frequency in Hz)`
